${patternList}

## 提取规则

### 1. 必须跳过的行
- 表头行、列名行
- 合计行、汇总行、小计行（含"合计"、"汇总"、"总计"、"小计"）
- 空行（金额为空或为0且无有效信息）
- 页眉页脚、说明行

### 2. 交易日期（tradeDate）
统一格式 YYYY-MM-DD，支持多种原始格式自动识别。

### 3. 金额提取（依据格式说明中的 amountStructure）

若 amountStructure = "debit_credit"：
- debitColumn 有正数值 → income=null, expense=该正数
- creditColumn 有正数值 → income=该正数, expense=null
- 两列都空或0 → 跳过此行

若 amountStructure = "amount_direction"：
- 方向列值 = directionDebitValue → expense=金额绝对值, income=null
- 方向列值 = directionCreditValue → income=金额绝对值, expense=null

若 amountStructure = "signed"：
- 负数 → expense=绝对值, income=null
- 正数 → income=该值, expense=null
- 0 → 跳过

### 4. 数字清洗
- 千分位逗号去掉：1,234,567.89 → 1234567.89
- 括号表示负数取绝对值：(100.00) → 100.00
- "—"、单独"-"、空白 → null

### 5. 流水号（serialNo）
从银行流水号、凭证号、交易序号等列读取，找不到填 null。

### 6. 余额（balance）
从余额列读取交易后余额，找不到填 null。

### 7. 收支类别匹配（categoryName / categoryType）

**优先级顺序（从高到低）：**

**第一优先：历史学习规律** — 若对方户名与学习规律中的记录完全匹配，直接使用对应的收支类别，无需再判断。

**第二优先：对方户名特征规则** — 必须从"系统现有收支类别"列表中选择，禁止自造新类别。

| 对方户名特征 | 对应类别 |
|---|---|
| 含"税务局"、"国税"、"地税"、"税务总局" | 税费支出 |
| 含"住房公积金"、"公积金管理中心" | 工资社保 |
| 含"社会保险"、"社保局"、"医疗保险"、"养老保险"、"失业保险"、"工伤保险" | 工资社保 |
| 含"工资"、"薪酬"、"人力资源"，且为支出 | 工资社保 |
| 含"水务"、"供水"、"电力"、"供电"、"燃气"、"电信"、"移动"、"联通"、"网络" | 水电费 |
| 含"租赁"、"物业"、"房屋租金"、"写字楼" | 租金物业 |
| 含"运输"、"物流"、"快递"、"货运" | 运输费 |
| 含"酒店"、"餐饮"、"餐厅"、"招待" | 招待费 |
| 含"差旅"、"机票"、"高铁"、"火车票"、"住宿" | 差旅费 |
| 含"利息"，且为来账 | 利息收入 |
| 含"利息"，且为支出 | 利息支出 |

**第三优先：备注摘要** — 结合摘要内容综合判断。

- income 有值（来账）→ categoryType = "收"，从收类别中选
- expense 有值（往账）→ categoryType = "支"，从支类别中选
- 无法判断或不确定 → categoryName = null，categoryType = null（宁可留空，不要猜测）

**不确定时务必留空**：若对方户名和备注均无法明确判断业务性质，categoryName 和 categoryType 一律填 null。宁可留空让用户手动补充，不要填错。

### 8. 对方科目（subjectCode / subjectName）

**优先级顺序（从高到低）：**

**第一优先：历史学习规律** — 若学习规律中该对方户名有对应科目，直接使用。

**第二优先：收支类别默认科目** — 若收支类别列表中已标注"默认科目"，直接使用该科目，无需自行判断，subjectCode 和 subjectName 填 null（系统自动从凭证模板匹配）。

**第三优先：仅以下 3 类需 AI 判断** — 从系统现有科目中选择最合适的：
- **销售收入**：判断"主营业务收入"还是"其他业务收入"等
- **服务收入**：同上，判断收入类科目
- **购买材料**：根据采购内容判断"原材料"、"库存商品"、"管理费用"等

其他所有收支类别的 subjectCode 和 subjectName 一律填 null。

只输出纯 JSON，不要包含 markdown 代码块（如 ```json```）：

{
  "bankName": "银行名称（来自格式识别）",
  "accountHolder": "账户持有人",
  "accountNumber": "本方账号",
  "transactions": [
    {
      "tradeDate": "YYYY-MM-DD",
      "income": 正数或null,
      "expense": 正数或null,
      "counterparty": "对方名称",
      "remarks": "备注摘要",
      "serialNo": "流水号或null",
      "balance": 余额数字或null,
      "categoryName": "系统收支类别名称或null",
      "categoryType": "收或支或null",
      "subjectCode": "科目编码或null",
      "subjectName": "科目名称或null"
    }
  ]
}
