## 处理规则

### 1. 编码规范化（按账套编码规则统一）
1. 去掉编码中的所有分隔符（.、-、空格）
2. 按编码规则重新分段，不足位数的末位补零
3. 示例（[4,3,3,2]）：原始"100101" → 判断层级后转为 "1001001"（一级4位+二级3位）
4. 已在系统中的科目以系统编码为准
5. **重要：每个原始科目必须有唯一的规范化编码，不同名称的科目绝不能归一化为相同编码。** 即使多个子科目看起来属于同一类别，只要原始编码不同、名称不同，就必须分配不同的规范化编码。例如"224105 个人法人"和"224106 李家新"必须分别对应 2241005 和 2241006，不能都变成 2241002。

### 2. 科目名称处理
1. 去掉前后空格、缩进符号（——、├、└、·等）
2. 识别并去掉父级名称前缀：
   - "应收账款.中国共产主义青年团高邮市委员会" → "中国共产主义青年团高邮市委员会"
   - "管理费用-办公费" → "办公费"
   - "应付账款/某供应商" → "某供应商"
   规则：分隔符（.、-、/、_、——、:）前面部分与父科目名称一致时，只取后面部分
3. 去掉编码前缀：如 "1001 库存现金" → "库存现金"

### 3. 父科目编码
- 根据编码层级关系确定 parentCode（规范化后的编码）
- 一级科目的 parentCode 为空字符串
- 如果父科目在系统已有科目中存在，使用系统中的编码

### 4. 余额方向判断（按优先级执行）
1. 系统已有科目 → 直接使用系统中的余额方向，不做修改
2. 新增子科目 → 继承父科目余额方向（递归向上查找到系统科目为止）
3. 备抵科目（无论是否新增）→ 余额方向 = 贷
   - 1602 累计折旧及其子科目
   - 1231 坏账准备及其子科目
   - 1702 累计摊销及其子科目
   - 科目名称含"减值准备"、"累计折旧"、"累计摊销"的
4. 新增一级科目按类型推断：
   - 资产类、成本类、费用类 → 借
   - 负债类、权益类、收入类、净资产类 → 贷

### 5. 过滤
- 跳过编码明显不是科目编码的行（如纯文字、空白）
- 保留所有有效科目（包括有子科目的父级，Java 会处理层级关系）

### 6. 输出顺序
按层级从小到大排序，同层级按编码排序，确保父科目出现在子科目之前。

---

## 输出格式

只输出纯 JSON，不要包含 markdown 代码块（如 ```json```）。

字段约定（用短 key 节省输出长度）：
- a = 原始编码（与输入列表中的编码完全一致，不做任何修改）
- b = 规范化后的系统编码
- c = 科目名称（不含父级前缀）
- d = 父科目编码（规范化后），一级科目填空字符串
- e = 类型（资产/负债/权益/成本/损益）
- f = 余额方向（借或贷）

**重要：值为空字符串的字段直接省略不输出。**

示例：
{"s":[{"a":"1001","b":"1001","c":"库存现金","e":"资产","f":"借"},{"a":"100201","b":"1002001","c":"中国银行（人民币）","d":"1002","e":"资产","f":"借"}]}
